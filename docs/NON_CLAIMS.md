# JianMu Non-Claims

本文档明确列出当前项目**不能证明**的内容，以防止过度解读或误导性引用。

---

## 当前项目不能证明

| 声明 | 原因 |
|------|------|
| 通用代码智能 | 系统仅在 C 语言整数求和这一极小域内验证，无法推广 |
| 大规模可扩展性 | 专家集合为手工设计，未在更大程序域测试 |
| 替代大语言模型（LLM） | 系统不具备语义理解、自然语言生成或跨域泛化能力 |
| 替代编译器 | 系统依赖 GCC 作为正确性 oracle，而非自行验证语义 |
| 真实软件工程任务有效性 | 未在任何真实代码库或工程任务上评估 |
| 训练成本低于大模型 | 系统无训练过程，但专家设计成本未与模型训练成本对比 |
| 任意程序生成 O(1) | 专家组合路径搜索未经复杂度分析，不保证常数时间 |
| 组合泛化的普遍性 | 仅验证加法操作数扩展这一特定结构变换 |

---

## 当前项目只能证明

1. 在极小程序域（C 语言整数求和）内，结构专家组合可以从两数求和扩展到三数/四数求和。
2. GCC 编译器反馈可以作为确定性的程序正确性信号，内联于生成流程中。
3. Trace Cache 可以记录并确定性复现成功的结构路径。
4. 有限的自然语言变体可以被归一化为同一结构化 Intent。

---

## 引用建议

引用本项目时，应将其定位为：

> 一个在极小程序域内验证 compiler-validated compositional structural generalization 可行性的研究原型，而非通用代码生成系统。
